# AGENTS.md

Palindromaker: a React 19 + TypeScript (strict) single-page editor for crafting palindromes, built on TipTap 3 (ProseMirror) with two custom extensions, toolchained on Vite+ (Vite 8 + Vitest + Oxlint + Oxfmt via `vp`).

## Commands

Toolchain lives in `vp` (installed automatically as a devDependency; scripts run it through pnpm).

| Command                       | Purpose                                       |
| ----------------------------- | --------------------------------------------- |
| `pnpm dev`                    | Dev server at http://localhost:5173           |
| `pnpm test`                   | Unit tests (Vitest), single run               |
| `pnpm test:e2e`               | Playwright (Chromium), auto-starts `pnpm dev` |
| `pnpm build` / `pnpm preview` | Static build to `dist/` / serve it            |

- `pnpm check` = format + lint + typecheck (`vp check`) **plus unit tests** (`vp test run`) — a full check. Type checks run through Vite+'s bundled tsgo because `lint.options.typeCheck` is on in `vite.config.ts`; there is no separate `typecheck` script.
- `pnpm deploy` (`wrangler deploy`) builds via `build.command` in `wrangler.jsonc`, which is `vp check && vp build` — a failing check or test blocks the deploy.
- Deploys are Cloudflare Workers Builds on GitHub pushes (main → production, other branches → preview URLs); GitHub Actions (`.github/workflows/ci.yml`) only checks — it uses `voidzero-dev/setup-vp` (which reads the pinned `vite-plus` catalog version and caches dependencies) for a `vp check` + `vp test run` job on Node 24, then a Playwright e2e job that uploads `test-results/` on failure.
- `e2e/shoot-app.mjs` (manual, dev server running) screenshots the app at three breakpoints into gitignored `screenshots/`; `e2e/resolve-playwright.mjs` re-exports Playwright's chromium because pnpm does not hoist it.
- Single test: `pnpm test src/lib/mirror-edit.test.ts` (filters are passed through to Vitest).
- One environment: `pnpm exec vp test run --project unit` (node) or `--project dom` (happy-dom).
- Pre-commit (`.vite-hooks/pre-commit` → `vp staged --fail-on-changes`, configured in the `staged` block of `vite.config.ts`) runs Oxfmt, Oxlint `--fix`, and `vitest related --run` on staged files. The `.vite-hooks/_` dispatcher is gitignored and recreated by `vp config` (the `prepare` script) / `vp hooks enable`. `VP_GIT_HOOKS=0` (or `HUSKY=0`) disables hooks per environment.
- `prepare` is deliberately `vp config --no-agent`: a bare `vp config` also updates coding-agent instruction files (this one included), and the project opts out — don't run `vp config --agent` expecting to keep hand-written content here.
- Version policy: `vite-plus`, and the `vite`/`vitest` pins in the `pnpm-workspace.yaml` catalog, stay in lockstep — `vite` is aliased to `@voidzero-dev/vite-plus-core` and `vitest` is pinned to the version `vp test` bundles (`vp toolchain` prints the pair). Don't bump them independently.

## Conventions

- Path alias `@/*` → `src/*` (configured in both `tsconfig.json` and `vite.config.ts`).
- `verbatimModuleSyntax` + `noUnusedLocals/Parameters` are on: type-only imports must use `import type`.
- Tests are colocated in `src/`, and the extension picks the environment (two Vitest projects in `vite.config.ts`): `*.test.ts` is plain logic in node, `*.test.tsx` renders React in happy-dom with Testing Library (`src/test/setup.ts` registers RTL's `cleanup`, which does not self-register without Vitest globals). `e2e/` is Playwright, excluded from Vitest. Note `test.exclude` at the root does not cascade into projects.
- Tests import from `vite-plus/test` (Vite+ re-exports upstream Vitest); `declare module 'vitest'` augmentations stay on the upstream module.
- Oxlint lint/format config lives in the `lint`/`fmt` blocks of `vite.config.ts` (the ESLint rules were ported by `vp migrate`; `@eslint-react` runs through Oxlint's JS-plugin bridge).
- Component tests use Testing Library only; there is no `jest-dom` or `user-event`, so assert on `textContent`/`getAttribute` and drive the UI with `fireEvent`.
- `src/lib/` is framework-agnostic (no React); React hooks live in `src/hooks/` and components in `src/components/`.

## Architecture

- `src/lib/check-palindrome.ts` — core algorithm. Normalizes (NFD, strips combining marks, lowercases) and pairs only letters (`\p{L}`). Returns `isPalindrome`, `mirror[]`, `center` (innermost matching pair, `undefined` when nothing matched) and `gap` (inclusive range of unpaired letters, `undefined` while the text reads the same both ways).
- `src/lib/doc-analysis.ts` — the document as the checker sees it, and the only place that bridges doc positions and text indexes. `analyzeDoc()` walks the doc once and returns `text` (normalized per character, so indexes stay aligned with `positions`), `positions` (text index → doc position; `undefined` for `\n` block separators and normalization expansions), `posToIndex`, `letterPositions` (letter ordinal → doc position) and the `checkPalindrome` `result`. Memoized in a `WeakMap` keyed by the (immutable) doc node, so both extensions analyzing the same keystroke cost one pass.
- `src/lib/palindrome-extension.ts` — TipTap `Palindrome` extension; drives center/gap/caret highlights via ProseMirror decorations and caches the analysis plus the doc-only decorations in plugin state, so caret moves only rebuild the caret decoration.
- `src/lib/mirror-extension.ts` — TipTap `MirrorEditing` extension; an `appendTransaction` plugin duplicates/deletes mirrored characters — but only while the pre-edit text is a palindrome; otherwise edits pass through untouched. Only reacts to single-step `ReplaceStep`s, ignores its own edits (`{ own: true }` meta) and IME composition. Position math lives in `src/lib/mirror-edit.ts` and counts in "letter space" (punctuation/separators invisible) off `letterPositions`. Options: `enabled` seeds the toggle (restored from prefs, so no toggle transaction after mount) and `onChange` fires when the toggle command runs — that is where the preference gets written. The `insertWord` command (the word finder's rows) inserts a word through the `word-insert` planner in one transaction, marked `{ own: true }` like the plugin's own mirror edits; `wordInsertMode()` is what both the command and the finder's hint read to know what a click will do.
- `src/lib/word-insert.ts` — planning for clickable result rows: an internal `planWordInsert()` returns the doc positions, texts and resulting caret for inserting a word the way mirror typing inserts a character — the word at the caret, `mirrorWord()` at the symmetric point in letter space. At the center in letter space (the empty document is this case) a word that already reads the same both ways goes in alone, any other word brings its mirror in beside it; when the text is not a palindrome, or mirroring is off, the word goes in at the caret alone and nothing is ever deleted. Spaces are inserted only where a letter would otherwise fuse with the new word — invisible to the checker, so they can never break a palindrome. `wordInsertTransaction()` wraps the plan as one transaction (both halves and the caret, so undo removes them together); `WordInsertMode` ("mirrored" | "caret" | "paused") is the one vocabulary shared by the command, the editor and the finder's hint.
- `src/lib/editor-schema.ts` — the one restricted TipTap vocabulary every surface sharing a palindrome speaks: StarterKit with most extensions disabled (paragraphs + text, no marks), the full editor extension list (`extensions(mirror)`), the reader's list (`readerExtensions()`: the same restricted StarterKit + `Palindrome` without `MirrorEditing`, plus `ReadOnlyContent`, a `filterTransaction` plugin that drops every doc-changing transaction), and the `schema` (`getSchema(extensions({}))`) that `persistence.ts` validates stored docs against. `src/lib/editor-schema.test.ts` pins that both lists speak the same nodes/marks and that shared text is schema-valid.
- `src/lib/persistence.ts` — debounced `localStorage` persistence, and the only module that touches the global: `localStorageOrNull()` returns the storage or null, since reading `window.localStorage` _throws_ when the browser blocks site storage (iframe, cookies disabled) and would otherwise crash the app before it renders. Every storage function takes that value, so tests inject their own. `readStoredDoc()` loads and validates the stored doc JSON against the editor schema (null on anything unexpected — including parseable-but-unrenderable docs, which would otherwise crash render) for the editor's initial content; `createPersistence()` saves on editor updates and flushes on destroy/unload/tab-hide, returning `{ detach, resolveConflict }` (detach is the React effect cleanup in `editor.tsx`). Because every tab shares one stored doc, it also listens for `storage` events: a tab the user has not edited adopts the incoming doc silently, a tab that _has_ been edited raises `onConflict` and stops saving until `resolveConflict("theirs" | "mine")` answers it (`src/components/conflict-notice.tsx`). Saves also compare storage against the last string this tab wrote, so a frozen tab that missed the event still cannot clobber it.
- `src/lib/dictionary.ts` — word finder dictionaries: lazily fetched per language (cached promises); `buildDictionary()` keeps raw + normalized words and a normalized `Set` used by `mirrorMatch()` to mark rows whose mirror is also a word ("pair") or is itself a palindrome. The load path uses `buildDictionaryIncrementally()`, which runs the same generator in ~20k-line slices and yields the main thread between them (`scheduler.yield()`, falling back to a timer); `buildDictionary()` runs it to completion and is what tests use.
- Word finder UI: `src/hooks/use-dictionary.ts` owns loading as one value (`idle | loading | ready | error`, where `loading` is derived from "no answer yet for this language") so a failed or pending language cannot leave the previous one's words on screen; `src/components/word-finder.tsx` holds the query/language/mode state and derives results with `useMemo` (search input debounced ~150ms by `src/hooks/use-debounced-value.ts`), while the panel's open/close state lives in `editor-page.tsx` (persisted as the `finderOpen` pref) and arrives as props; `word-finder-controls.tsx` is the query/language/mode row and `word-finder-results.tsx` owns the virtualizer; each result row is a button that asks `editor.tsx` (via `onInsertWord`) to insert its word at the caret, and the panel's hint line under the controls says what a click will do for the current `WordInsertMode`. The hook and the panel are tested with `loadDictionary` mocked (`use-dictionary.test.tsx`, `word-finder.test.tsx`), which is where the "a stale or failed language leaves no words behind" rule is pinned down.
- `src/lib/i18n.ts` — UI language (the same six the finder's dictionaries cover: "pt" | "en" | "es" | "de" | "fr" | "it", with the pt-br dictionary mapping to the "pt" UI code; distinct from the dictionary `Language`/`lang` pref): the `messages` table (`en` defines `MessageKey`; every other table is `Record<MessageKey, string>`, so the compiler forces key parity), `UI_LANGUAGE_LABELS` (native names), `UI_LANGUAGE_LOCALES` (per-language number formatting for result counts), `resolveUiLanguage()` (stored pref wins, then `navigator.languages` matched on the primary subtag, else "pt"), and a module store (`initUiLanguage` runs once per page load from `App.tsx`, then `setUiLanguage`). `src/hooks/use-i18n.ts` exposes `{ lang, t }` via `useSyncExternalStore`, so a switch re-renders consumers without a provider. The module defaults to "en" when nothing initializes it — that is what keeps unit tests, which never mount `App`, asserting English strings. The switcher (`src/components/language-switcher.tsx`, a select in the header with native labels) writes the `uiLang` pref; `App` also mirrors the language onto `<html lang>` through `UI_LANGUAGE_TAGS` (`pt` maps to `pt-BR`, matching the static `index.html`). The editor's initial content and aria-label are mount-time values and deliberately do not follow a mid-session switch.
- `src/lib/sample.ts` — starter text shown only when storage holds nothing usable: `SAMPLE_CONTENT_BY_LANG` maps every UI language to a real palindrome of its own ("A grama é amarga" pt, "Anita lava la tina" es, "Trug Tim eine so helle Hose nie mit Gurt?" de, "Élu par cette crapule" fr, "I topi non avevano nipoti" it), picked by `sampleContent(lang)`; its own module so the e2e suite can assert on it without importing TipTap. The e2e suite runs with Playwright's default en-US locale, so its `SAMPLE_CONTENT` assertions hold wherever the UI language resolves to en; the pt path is covered by the `pt-BR browser locale` describe, which pins `test.use({ locale: "pt-BR" })`.
- Sharing: `src/lib/share-link.ts` (node-tested) is the share format — `buildShareUrl()` puts the raw text percent-encoded into a `/p#t=` fragment (no backend; the fragment IS the payload), and `readShareText()` parses it back: null for anything that is not a well-formed `t=` fragment (a raw `&` means foreign parameters, malformed percent-encoding, a decode past `MAX_SHARE_TEXT`) and `""` for a present-but-empty param — callers treat every falsy as "no share". `textToDoc()` turns shared text into paragraph JSON, not a string (string content is HTML-parsed, where `\n` is whitespace). `src/lib/clipboard.ts` is the one clipboard touchpoint, shaped like `localStorageOrNull()`: `clipboardOrNull()` guards the blocked-permissions throw, `copyText()` never rejects. `src/components/copy-button.tsx` is the one transient "Copied!" implementation — the visible label renames the button and an sr-only `role="status"` live region announces it for screen readers (a renamed button is not announced on its own), 2s timer. The Share button (`status-bar.tsx`) is gated on `hasLetters && isPalindrome && text ≤ MAX_SHARE_TEXT` computed in a `useEditorState` selector off plugin state; the empty doc is a vacuous palindrome and does not count, and the disabled title says why (`share.disabled`, or `share.tooLong` when only the cap blocks).
- The `/p` reader: `src/components/reader-page.tsx` reads the fragment once on mount (`useState` initializer) — anything falsy gets the friendly empty card with a back link. `src/components/reader.tsx` renders the same card/typography/legend as the editor on the restricted reader list (`editor-schema.ts`) but — deliberately — an **editable** TipTap view: PM's keydown/caret machinery is gated on `view.editable`, browsers do not move carets inside `contenteditable="false"` content, and hand-rolling arrow navigation hits PM's non-editable selection sync (all three verified) — so read-only-ness is enforced on two layers. Event level: `handleDOMEvents` claims `beforeinput` (typing, IME commits, paste, cut), `paste` and `drop` with `preventDefault` + a truthy return, which also keeps PM's own handlers out. State level: the reader list carries `ReadOnlyContent`, a `filterTransaction` plugin that drops every doc-changing transaction — PM state (and therefore Copy, reload, any future share) can never change even if the event level is bypassed, though an uncancelable IME commit can paint transient DOM text that relies on PM reverting it from state (accepted; event-level paths verified against Chromium, the IME path by source-reading). Arrows, shift-extend and text selection stay native. `role="region"` + aria-label keeps assistive tech out of textbox semantics. e2e (`share.spec.ts`) pins the typing-inertness, arrow navigation across paragraphs and the axe audit; "Copy text" copies the plain text; "Edit this" is a `<Link to="/">` carrying the same `#t=` fragment.
- Routing: `src/router.tsx` — TanStack Router, code-based routes (no Vite plugin; `@tanstack/react-router` only). The root route is the shell (sticky `SiteHeader` + `<Outlet/>` inside a `flex min-h-dvh flex-col` wrapper, which is also what scrolls the page back to the top on navigate), the index route renders `src/components/editor-page.tsx` (the old `App.tsx` content, minus the header row: brand, links and the language select moved to the site header; the tagline and an sr-only h1 stayed here), `/about` renders `src/components/about-page.tsx`, and `/p` renders `src/components/reader-page.tsx` (reached only through shared links — deliberately not in `NAV_ENTRIES`). A future page is one entry in `src/lib/navigation.ts` (`NAV_ENTRIES`, plain `{ path, labelKey }` data the header maps over) plus one route here. `src/components/site-header.tsx` is the sticky navbar: desktop row (brand left, nav links + language select right), and on phones a `MobileMenu` mounted keyed by the pathname — remounting resets its open state, so navigation closes the panel without an effect; the panel carries `aria-expanded`/`aria-controls`, Esc (refocusing the ☰) and outside-click close, and its links also close it because a same-page click never changes the route. `App.tsx` is a thin shell: `initUiLanguage`, the `<html lang>` effect, and `<RouterProvider router={router}/>`.
- `src/components/editor.tsx` — gets its extension list and `schema` from `src/lib/editor-schema.ts`; storage is read once (a `useState` initializer) for the initial content with the precedence **shared `#t=` fragment > stored doc > sample** (`src/lib/sample.ts`, its own module so the e2e suite can assert on it without importing TipTap), and for the mirror toggle passed to `extensions()`. The fragment is read once and consumed by a mount `history.replaceState` effect, so a reload after "Edit this" falls back to storage; editing a shared palindrome replaces the stored doc on the first edit (accepted silent replace — the conflict rules that then govern saving live in `persistence.ts`). Renders the card: StatusBar (`src/components/status-bar.tsx` — the card's footer: palindrome status, the mirror toggle, and the "Find words" trigger that opens/closes the finder panel), the cross-tab conflict notice, and the editor; the WordFinder and the always-visible color legend (`src/components/legend.tsx`) render outside the card as siblings. `src/components/editor-page.tsx` (the home route) owns the finder's open/close state (persisted as a pref, returned focus to via the trigger ref). The finder's `insertMode` comes from a `useEditorState` selector that returns the derived mode (not the state behind it), so keystrokes that leave what a click would do unchanged never re-render the panel and its result list; the insert callback chains the `insertWord` command with `.focus()` so typing can continue right after a click. The finder's fixed panel docks at `md:top-16` to clear the sticky header.
- GoatCounter: `src/lib/goatcounter.ts` — analytics, React-free. `initGoatcounter()` (called from `src/main.tsx`) injects the count script only when `VITE_GOATCOUNTER_URL` is set (see `.env.local.example`), configured `no_onload` so nothing counts by itself; the router (`src/router.tsx`) calls `countRoute(pathname)` for every route, first included, so full page loads and SPA navigations are symmetric, and a navigation that beats the script load is flushed on its load event.

## Gotchas

- `RouterProvider` resolves the router's initial location asynchronously and
  its first render is empty: component tests that wrap components in a
  memory-history router must await the routed content before querying (see
  `site-header.test.tsx`).
- happy-dom has no layout, so a virtualizer measures a 0px scroll container
  and renders **no rows**: component tests can assert the results header and
  the panel's states, but never a row. `ResultRow` is exported for that
  reason and tested directly; the virtualization itself is only observable
  in Playwright.
- The slow keystroke pacing in `e2e/palindromaker.spec.ts` is needed for
  ProseMirror's selection sync to keep up with synthetic CDP input; it is
  relied upon, don't "optimize" it away.
- Playwright's webServer reuses whatever is already listening on 5173
  (`reuseExistingServer`): a stale dev server from another toolchain state
  makes the whole e2e suite fail with render timeouts for no test-visible
  reason — `lsof -nP -iTCP:5173 -sTCP:LISTEN` and kill it first.
- Playwright tests need Chromium installed: `pnpm exec playwright install chromium`.
- Decoration styling mixes inline Tailwind classes (e.g. `bg-blue-200`, `bg-red-300`, `bg-purple-200/400`) with `pm-center1`/`pm-center2` rules in `src/styles/globals.css`; the e2e suite asserts on these class names.
- `e2e/navigation.spec.ts` opens `/about` directly and expects it to render; that relies on `not_found_handling: "single-page-application"` in `wrangler.jsonc` (the static host serves the SPA for every path) — a local preview that lacks the fallback will fail this test.
- `e2e/share.spec.ts` copies the link by clicking the Share button, whose "Copied!" feedback **renames the button**: locate asserted states by the copied name, not the resting one. In the viewer, two click pitfalls remain (generic PM): the click bounds center can fall past the line's end and decoration spans swallow clicks — click a paragraph at a small `position` offset. Clipboard coverage grants `test.use({ permissions: ["clipboard-read", "clipboard-write"] })` and polls `navigator.clipboard.readText` because the read races the copy.
- Don't move the dictionary build into a Web Worker without measuring first: es is 635k words, and structured-cloning the built dictionary back to the main thread was measured at ~213ms against ~282ms to build it, so a worker buys almost nothing. Slicing the build (above) removed the blocking instead. Loading es still costs ~97MB of heap; cutting that needs a different data structure (one flat string + offset/hash `Uint32Array`s, which _are_ cheap to transfer), not a worker.
